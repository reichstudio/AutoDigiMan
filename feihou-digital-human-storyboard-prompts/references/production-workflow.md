# 可复刻数字人口播生产工作流

此流程适用于有锁定口播脚本或需要 AI 协助形成脚本的数字人口播视频；讲者人数、性别、场景类型与视觉风格由用户输入定义。用户给出文件夹路径时，先扫描其中的文档并从中提取制作要求和台词。时间轴来自用户提供的实测时间点，或明确标注 `预估` 的脚本推导。三张生产页、资产编号、口播时间轴和 H3 提示词由同一份项目数据派生。

## 0. 启动前输入检查

全程遵守 [conversation-confirmation.md](conversation-confirmation.md)：用途和两次阶段确认在对话内完成，优先使用原生选择提示框；大纲和资产建议不得保存成页面。目录主题不能代替用户用途选择。

1. 用户给出文件夹路径时，先执行 [input-intake.md](input-intake.md) 的文档扫描。逐份归类制作要求与口播台词；冲突或不清晰的来源先请用户确认。把采用内容记录到内存项目数据的 `source_documents`、`production_requirements` 与 `locked_script_source`，而不是写入项目 JSON 文件。
2. **先盘点资产信息**：核对文档来源、人物/场景/产品/道具图、参考音色、参考视频和数字人用途。每项现有资产都只按实际已读取的内容记录其可用角色；音色仅用于音色/语气参考，时间统一为 `00:00:000–00:00:000`，不得作为口播母带、背景音或镜头节拍。
3. 文档、视觉图、音频或视频缺失时，按 [input-intake.md](input-intake.md) 的固定选项逐类让用户选择。用户的选择是项目约束：“稍后提供”不冒充已经引用；“不需要资产图”使用文生视频策略；“直接生成需要的资产图”仅在图确实生成并检查后才登记 `P#`。
4. **第一次确认**：向用户提交仅包含资产与参考内容的确认表——文档来源/采用要求、锁定台词来源和字数/段数、现有 `P#` / `A#` / `V#`、用途及缺项选择。先由用户确认可提供哪些资产；此时不写分镜大纲、资产图提示词或 H3 正式提示词。
5. 第一次确认后，记录用户的硬时间点、段落划分、台词要求、镜头时长、参考图格式要求、出镜安排和四个项目定义项（成片总时长或口播音频、画幅与分辨率、口播语言、视觉风格基调）。用户未提供时使用默认值——预估时间轴（语速假设）、3840×2160 16:9 横版、中文、写实演播室——并在后续大纲中标明。电商带货同步确认正常切镜或快剪，并记录 `pacing_style`。
6. 真人IP复刻收集参考视频并完成讲者特征分析：外观、动作习惯、表情与眼神、语速节奏、镜头习惯；用户选择不提供时明确切换为简化复刻。
7. 规划分镜前读所选用途的场景规则条目（[scenario-rules.md](scenario-rules.md)），按其结构模板、分镜序列、景别与节奏默认值设计镜头表；用户输入与官方 H3 框架优先于场景默认值。

## 1. 分镜大纲、资产缺口与第二次确认

1. 第一次确认后才提出大纲：总镜数，以及每镜 `编号 · 段落 · 预估 seconds · 一句画面/讲解概述`。这一步只用于确认内容与结构，不写完整机位动作、可复制 H3 提示词或资产图提示词。
2. 依据大纲列两份清单：
   - **已有资产清单**：仅列实际存在和已经查看的 `P#` / `A#` / `V#`，写明各自可服务的镜头与可承担的画面职责；
   - **补充资产内容清单**：逐项写明主体、构图/景别、可见内容、状态、用途和服务镜头，但此时不写图像生成提示词。
3. 不以节省资产图为目标。只要计划镜头与任何现有图在构图、景别、主体可见内容、交互、产品状态、服装状态、场景状态或连续性锚点上有明显差异，即列入补充资产；不得把不匹配图硬塞进 `<Picture N>`。
4. **第二次确认**：把分镜大纲和两份资产清单一起交给用户确认。确认前允许用户修改大纲、增删镜头、调整资产或提出新要求；发生修改时同步更新大纲与两份清单并再次确认。第二次确认前不得开始正式资产提示词、H3 提示词或中文分镜列表。

## 2. 脚本与时间轴

1. 锁定脚本文件决定正文、语言、标点和句序；分镜与提示词按其原文工作。
2. 用户已提供口播录音时，采用用户提供的总时长与逐句/逐段时间点作为硬约束；归一到 0.1 秒的 `MM:SS:ddd`（末位毫秒为 0）。
3. 用户未提供时间点时，按所选场景的语速档位（快 240–260 / 中 200–240 / 稳 160–200 字/分钟，档位表见 [scenario-rules.md](scenario-rules.md)；真人IP复刻取参考视频实测）建立预估句级边界，全部标注 `预估`，并在交付说明中注明成片录音后按实测校时。
4. 每个完整口播句子放入一个镜头；单元调整时同步更新 `seconds`、口播字段、提示词与镜头卡；不得创建音频切片。
5. 全片镜头按列表顺序拼接，完整时长为所有 `seconds` 之和；页面 `range` 固定显示 `00:00:000–00:00:000`。

## 3. 资产登记与参考图计划

1. 第二次确认后，逐张查看实际参考图，再建立全局资产登记表。每张图获得一个永久 `P#` 和准确简短名称；名称与描述以画面实际内容为准。
2. 优先复用经过大纲核验的用户已有讲者、场景、道具和产品图；只为已经确认的补充资产清单编写 GPT Image 2 生成提示词。
3. 资产页前部放置可点击的 `P# → 内容标题` 速查表；每个锁定资产与生成资产都能跳转到对应卡片。讲者、产品、道具如要求生产卡格式，采用左侧特写、右侧正侧背三视图的 16:9、4K 卡片。
4. 为每个 H3 镜头先选定有序的 `P#` 上传列表，再换算镜头局部 `<Picture N>`。一条 H3 单元最多九张视觉图；组合图用于多人或编队构图，单人图用于身份和近景，状态/场景图用于空间与连续性。

## 4. 分镜与 H3 提示词

正式严肃场景先执行 SKILL.md「正式严肃场景的固定机位规则」：新闻播报（含油管新闻）、政企讲解、教育网课等默认 `Static Shot`，相邻单元可保持同一主讲构图。以下关于运镜、镜头差异和内部切镜的通用建议不构成强制运动要求；仅为内容展示所必需时切至其他固定机位。最终检查中英文提示词和中文列表，移除未经用户要求的推拉摇移、变焦及漂移描述。

1. 第二次确认后，以已确认大纲为骨架建立覆盖完整口播时长的正式镜头表，再写提示词。单元默认 10–15 秒、尽量贴近 15 秒上限，时长由内容决定；每个单元默认单镜头连续，景别/机位变化用单元内 `[Shot N] At MM:SS.mmm` 内部切镜完成；电商带货快剪风格以约 15 秒单元内 2–3 秒一次的高密度切镜实现，卖点之间在单元内切镜转换。按场景语速档位折算单元字数容量（稳档 15 秒约 40–50 字、中档 50–60 字、快档 60–65 字），把脚本句子聚合为单元，人物动作剧情与所讲内容在同一单元内完成。每个镜头给出开始状态、主事件、镜头关系、结束状态，以及与前后镜头的连续或硬切类型。
2. 出镜口播镜头在 `detailed_description` 中绑定讲者稳定 `(Sx)`，并用 `<d>[语言] 原文</d>` 写明本镜完整台词与精确口型；B-roll 插入画面承载同一画外音，语音由 `<Audio N>` 与口播音频承载。
3. 每个 H3 `detailed_description` 按固定叙事顺序书写：
   - 画面质感与具体用光：光源、方向、软硬、补光、反射光、轮廓光和曝光关系；
   - 构图与主动态：焦段镜头拍摄、相机起点、讲者/产品/环境位置和主事件；
   - 按可见与可听顺序的完整连续讲话、动作、运镜和切镜；
   - 终帧：讲者姿态、相机轴线、环境、道具/产品/特效和光照的可延续状态。
4. 用自然、完整、可执行的句子写提示词。每个引用资产在 `subject_definitions` 中通过其局部 `<Picture N>` 和全局 `P#` 定义，之后始终使用相同的简短规范名称；提示词以正面陈述描写目标画面。
5. 讲者走位、操作演示或复杂节奏可采用 `[Shot N] At MM:SS.mmm` 的内部硬切；每一段说明具体起始机位、讲者路线、手势与讲解点的对应、操作/演示结果、环境反馈、镜头轨迹和终帧。
6. 非硬切衔接的下一镜首帧复述前一镜的终帧状态；硬切声明新的构图、焦段、相机轴、用光和主动作，呈现与上一镜不同的视觉前提。
7. 动笔前读官方通用指南与所选模式指南；提示词的标签、字段顺序、时间标注与声音段规则以官方速查（SKILL.md「官方规则速查」）和完整官方文档为准。

## 5. 三页生成与交互

1. 只有收到用户对对话内展示的大纲及资产清单的第二次确认后，才按 [page-data-contract.md](page-data-contract.md) 在内存中组装正式全局资产和镜头数据，并传给校验器和页面构建器。**不得**创建或交付 `project-manifest.json`；只有正式制作内容进入三张 HTML 页面，所有建议与确认继续在对话中完成，不创建额外页面。
2. 使用技能包中的三份空白模板，通过标准输入运行项目数据校验器和页面构建器。页面保持自包含：数据、样式、复制、筛选、搜索、跳转和返回顶部功能全部内联；每页使用单一权威渲染器，加载后最终卡片的样式类保持稳定。若环境强制需要临时 JSON，只能放在系统临时目录，并以 `try/finally` 删除。
3. H3 页和中文分镜页每张卡均显示固定全零时间、直接来自 `seconds` 的时长、本段口播、分类与单独边框的 `P#` 图片编号；资产页的速查表为五列可点击标签。时间标签点击复制全零 token，并在页面上方中央显示清晰的"已复制"提示。
4. 数字人页面不提供口播主音轨载入或按时间切片试听；音色文件仅作为完整参考随 H3 单元上传。
5. 使用深色制作面板样式时，页眉采用左到右的深蓝至低饱和紫渐变，正文从顶部向近黑色纵向渐变；所有页面保持一致的卡片层级、标签样式与返回顶部按钮。

## 6. 正式稿后资产引用复核、交付前审核与迭代

1. 正式资产提示词、H3 提示词和中文分镜列表全部完成后，先逐镜复核资产引用：每个 `P#` 必须真实存在、可服务该镜的构图/景别/可见内容/状态和连续性，局部 `<Picture N>` 必须按上传顺序正确映射。不可因资产已有而牵强引用。
2. 复核发现关键画面没有合格资产时，向用户给出“建议追加资产”清单，说明原因、所服务镜头和需要改写的引用；由用户选择是否追加。未获选择前不自动生成新增资产提示词，也不修改已交付镜头引用。用户选择追加后，生成相关资产提示词并同步修改受影响的 H3/中文镜头，随后重新做本节复核。
3. 再做数据审核：所有 `seconds` 之和正确、口播句子完整落在单元内、页面 `range` 全为零、无 `audio_slice` 或 `master_audio`、出镜/插入占比达到已确认目标；时长估算依据已在交付说明中写明。
4. 做 H3 与画面逻辑审核：每镜视觉 `P#` 不超过九个、参考音色不超过三个，所有引用图在正文中有实际画面职责，讲者/场景/产品名称一致，`<d>` 台词与当前单元一致；相邻镜头的连续或硬切关系明确；讲者路线、操作演示、空间状态、镜头运动和用光可解释。
5. 渲染后审核页面：刷新后仍保留分类徽章、图片编号样式、筛选、快速跳转、复制按钮、时间复制提示和回到顶部按钮；所有内联脚本解析正常，最终页面由权威渲染器生成。
6. 根据用户对生成结果的反馈，只修改受影响的镜头、资产引用、中文分镜卡和对应中英文提示词，再重复本节审核；保留已通过的旧版本，除非用户明确要求覆盖。
